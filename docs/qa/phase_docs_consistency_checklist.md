# Phase Docs Consistency Checklist

Используй этот чек перед завершением любой новой фазы документации.

## 1) Структура фазы
- [ ] Есть `README.md` фазы
- [ ] Есть `01_phase*_step_by_step.md`
- [ ] Есть `02_phase*_checklist.md`
- [ ] В `README.md` есть ограничения scope

## 2) Качество инструкций
- [ ] Шаги идут по итерациям (от ассетов к интеграции)
- [ ] Для ключевых функций есть node-by-node
- [ ] Нет «догадайся сам» формулировок
- [ ] Ясно указано, что не делается в фазе

## 3) Архитектурные правила
- [ ] Соблюдается `docs/phase0/06_blueprint_rules.md`
- [ ] Cast только в оправданных местах (инициализация/контролируемые точки)
- [ ] Частые обновления идут через таймер/события, не через бессмысленный Tick
- [ ] SRP: один компонент = одна зона ответственности

## 4) Кросс-фазовые стандарты
- [ ] Для interaction соблюдается `docs/system/interaction_l2.md`
- [ ] Следующая фаза указана в текущем `README.md`
- [ ] `docs/README.md` обновлен и содержит новую фазу

## 5) Проверяемость
- [ ] В `02_*_checklist.md` есть smoke test
- [ ] Есть Definition of Done
- [ ] Критерии DoD измеримы и проверяемы
